# App Flow Document

## Onboarding and Sign-In/Sign-Up

A brand-new visitor first lands on the public site at the main URL. They see a clean homepage with a navigation header offering links to Home, Gallery, Video, VTC KKP, and Dashboard PNBP. No sign-up prompt appears because public users do not create accounts. If someone needs administrative access, they click the “Sign In” button in the header. This takes them to the secure login page powered by Supabase Auth. On the sign-in page, the user enters their email and password and clicks “Continue.” If they mistype credentials, an in-page error message explains that the email or password is incorrect. A “Forgot Password” link under the form leads to a recovery screen where the user types their email and requests a password reset link. Supabase sends an email with instructions. At the bottom of the login form, there is no “Sign Up” option because only administrators are allowed and their accounts are created manually through the Supabase dashboard or an admin management page. Once authenticated, the user is redirected into the protected admin area. Signing out is available in the admin header as a “Sign Out” button, which clears the session and returns the visitor to the public homepage.

## Main Dashboard or Home Page

For public visitors who have not signed in, the default landing page displays a large image slider showing featured photos. Below the slider, a brief introduction invites visitors to browse the gallery or watch videos. The site header remains sticky at the top with links to each public page and the Sign In button. The footer at the bottom offers contact information and social media links. Navigating to the Gallery page reveals a responsive grid of image cards. Each card shows a thumbnail and title, and clicking it opens a full-screen modal or a new page with the larger image and description. The Video page lists video cards with a thumbnail and title. Clicking opens an embedded player directly on the page. The VTC KKP and Dashboard PNBP pages each display an iframe filling the main content area. These iframes load the external dashboards seamlessly and include a small header explaining the content.

For administrators who successfully sign in, the default view is the Admin Dashboard home. This dashboard uses a two-column layout with a collapsible sidebar on the left and a main content area on the right. The sidebar shows links for Slider Management, Gallery Management, Video Management, User Management, and Settings. A compact header at the top of the main area displays the current page title and a Sign Out link in the top right corner. From here, admins can click any sidebar link to manage specific content types.

## Detailed Feature Flows and Page Transitions

When an administrator selects Slider Management in the sidebar, the Slider page loads in the main area. The page fetches the list of slider images from Supabase and displays them in a data table. Each row shows the image thumbnail, title, display order, and action buttons for Edit and Delete. Clicking “Add New Slide” opens a dialog containing a form with fields for title, description, display order, and file upload. The admin chooses an image file, and on submission, a server-side action uploads the file to Supabase Storage, retrieves its public URL, and then inserts a record into the slider_images table. A toast appears to confirm success, and the table refreshes to show the new slide.

In Gallery Management, the flow is similar. The gallery grid appears as a table of images, each with Edit and Delete options. The admin clicks the edit button to open a dialog prefilled with existing data. Changing the title or replacing the file and saving triggers a server action that updates Supabase Storage if a new file is provided and updates the gallery_images record. After completion, the table reloads and a success notification displays.

For Video Management, the admin sees a table listing videos with columns for title, thumbnail URL, video URL, and actions. Adding a new video opens a form where the admin enters a YouTube or file-based URL and a thumbnail upload. On submit, the server action either uploads the thumbnail to storage or accepts the provided URL, then writes a new row to the videos table. The table refreshes to include the new entry.

The User Management page in the admin area lists all admin accounts. Each row includes the user’s email, role, creation date, and action buttons for Reset Password and Delete. Clicking Reset Password prompts confirmation, then triggers a Supabase admin function to email the user a reset link. Deleting a user calls a server action to remove them from the auth.users table. Whenever these actions complete, the page refreshes and a notification confirms the change.

Navigating between these pages never requires a full browser reload. The sidebar remains persistent, and clicking any link swaps the main content area. If an unauthenticated user somehow reaches a protected route, they are redirected back to the Sign In page.

## Settings and Account Management

In the Settings section of the admin area, administrators can update their own profile and preferences. The page displays a form with fields for Full Name and Preferred Theme (light or dark). Changing the theme updates a cookie so the site respects the choice on subsequent visits. A separate tab within Settings is dedicated to notification preferences, letting the admin toggle email alerts for new user signups, content changes, or system errors. Although public user signup is disabled, this section still exists for future use. After submitting changes in Settings, a server action updates the admin’s record in a Supabase profiles table. A success banner confirms the update, and the admin can then click “Back to Dashboard” to return to the home of the admin portal.

## Error States and Alternate Paths

If a public visitor tries to access an admin URL directly, they see a redirect to the sign-in screen. Invalid sign-in attempts show an inline error under the form fields. During file uploads, if the connection is interrupted, the dialog displays a message explaining the upload failed and provides a “Retry” button. When saving form data, if Supabase returns a validation error—such as missing title or unsupported file type—the form highlights the offending fields with red text. In the unlikely event of a server-side exception, a generic error page appears in the main area of the admin dashboard, offering a “Try Again” button and contact information for support. Loss of internet connectivity on any page triggers the browser’s native offline indicator, and after reconnection, any in-flight operations retry automatically where possible.

## Conclusion and Overall App Journey

A visitor lands on the public homepage, explores galleries, watches videos, and views external dashboards via iframes. If they need administrative access, they click Sign In and provide valid credentials to enter the protected area. Once authenticated, they manage slider images, gallery items, videos, and user accounts through a consistent admin dashboard interface. Every action, from adding a new slider image to resetting a colleague’s password, is handled by secure server-side code interacting with Supabase Auth, Storage, and Database. Throughout the experience, users receive clear feedback on success or failure, and the navigation always keeps them oriented within either the public site or the admin portal. This flow ensures both public content delivery and secure content management are seamless and intuitive.
